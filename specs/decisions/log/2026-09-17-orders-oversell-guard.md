---
date: 2026-09-17
title: Stop one-of-a-kind artwork overselling with a partial unique index on `orders(artwork_id) WHERE status <> 'canceled'`, plus moving the `isForSale` flip into the same transaction as the order insert, rather than only adding an application-level check
issue: 687
category: Architecture
---

`server/routes.ts`'s `POST /api/orders` checked `artwork.isForSale` before creating the order, but nothing ever set it back to `false` afterward, and the check-then-insert gap is a race regardless — two requests reading `isForSale: true` in the same window both pass. An app-level check alone (e.g. `SELECT ... FOR UPDATE` or a pre-insert existence query) narrows the window but does not close it without also serializing on something the DB enforces; the issue's own suggested fix was the unique index, so that's what closes the race for real. **Chosen:** (1) `shared/schema.ts` adds `uniqueIndex("IDX_orders_artwork_active").on(table.artworkId).where(sql`status <> 'canceled'`)` — Postgres enforces at most one active order per artwork independent of any request timing; (2) `storage.createOrder` wraps the order insert and `artworks.isForSale = false` in one `db.transaction`, so the common case (no race) leaves the artwork correctly flagged without a second round trip from the route handler; (3) a losing insert hits the unique index and throws a `23505`, which `createOrder` translates into a new `ArtworkAlreadySoldError` that `POST /api/orders` maps to `409` (distinct from the pre-existing `400` "not available" the fast-path `isForSale` check still returns for the non-racing case); (4) `storage.updateOrderStatus` re-lists the artwork (`isForSale = true`) in the same transaction whenever a transition lands on `canceled` — the issue's explicit re-listing requirement — covering `pending`/`communicating`/`sending`/`closed` → `canceled` alike, since `ORDER_TRANSITIONS` already allows canceling a closed (completed) order for a refund. Migration `0014_add_orders_artwork_active_unique.sql` is additive (`CREATE UNIQUE INDEX`, no `DROP`/`RENAME`/data statement) so it is autonomous under `AGENT-AUTONOMY-POLICY.md` §1 rather than gated. The MCP `create_order` tool needed no change — its existing generic `catch (e: any)` already surfaces `ArtworkAlreadySoldError`'s message. Reversible: drop the index (migration revert) and revert the three storage.ts/routes.ts hunks.
