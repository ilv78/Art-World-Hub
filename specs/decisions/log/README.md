# Decision log — one file per decision

Every architectural, infrastructure, security, or process decision gets **its own file**
here, added in the same PR as the change. One file per decision is what lets several PRs
land at once: new files never conflict on merge, where appends to one table always did
(#808).

**Filename:** `YYYY-MM-DD-<slug>.md` — the date the decision was made, then a short
kebab-case slug.

**Frontmatter** (all four required; `node script/decision-log.mjs --check` enforces it):

```yaml
---
date: 2026-09-17
title: One-line decision summary
issue: 808
category: Process        # Architecture | Security | Process | Infrastructure | Product
---
```

**Body:** the context and reasoning — what was chosen, what was rejected and why, what it
would take to reverse. Write it the way the frozen table's *Context* column was written:
dense, specific, with the evidence.

**Index:** `node script/decision-log.mjs` prints every entry as a table, newest first.
Nothing is committed as an index on purpose — a generated index would be regenerated by
every PR and conflict exactly as the table did.

The historical table (2026-03-10 → 2026-09-17, 135 rows) is frozen at
[`../DECISION-LOG.md`](../DECISION-LOG.md). Do not append to it.
